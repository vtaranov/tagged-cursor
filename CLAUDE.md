# Tagged Cursor

Фоновое приложение для macOS: показывает флаг текущей раскладки (🇷🇺/🇺🇸) над текстовым курсором. Флаг появляется при смене окна, поля ввода, раскладки, после клика и после паузы в наборе; исчезает при нажатии клавиши.

Основной пользователь — владелец проекта. Большую часть времени он работает **удалённо через Screen Sharing с Mac Studio** (кабель Thunderbolt), иногда — с клавиатуры самого MacBook. Оба режима обязаны работать.

Репозиторий публичный (github.com/vtaranov/tagged-cursor), тестеры собирают сами по `README.md` и пишут в Issues. В основном они работают с клавиатуры своего мака, у них другие приложения и могут быть Intel-маки (сборка под `uname -m`). README — для них: при изменении установки, поддерживаемых приложений или ограничений обновлять его.

## Команды

```bash
./build.sh      # сборка в build/TaggedCursor.app (swiftc, без Xcode)
./install.sh    # сборка + установка в /Applications + перезапуск
./test.sh       # юнит-тесты логики (Sources/Core)
./test-caret.sh # сверка probeCaret с эталонными полями AppKit (build/CaretHarness.app)
python3 scripts/backlog.py            # очередь требований
/usr/bin/log show --last 10m --predicate 'subsystem == "local.tagged-cursor"' --style compact
```

- Только Command Line Tools, Xcode нет. Swift 6 в режиме `-swift-version 5`.
- Тесты: Swift Testing через SwiftPM (`Package.swift` — цель только для `Sources/Core`, приложение по-прежнему собирается `swiftc`). Без Xcode нужны `platforms: [.macOS(.v13)]` и явные пути к фреймворкам — всё в `test.sh`. `#expect` не умеет вызывать mutating-методы: результат присваивать в `let`.
- Подпись: самоподписанный сертификат «Tagged Cursor Dev» в связке «Вход», создаётся `scripts/make-cert.sh`. Благодаря ему разрешение Универсального доступа переживает пересборку. Без сертификата `build.sh` откатывается на ad-hoc — тогда после каждой сборки разрешение надо выдавать заново.
- Установленная копия — `/Applications/TaggedCursor.app`, в автозапуске через `SMAppService`. Не запускать параллельно копию из `build/`.
- `log` в zsh — встроенная команда, использовать `/usr/bin/log`. Писать диагностику уровнем `notice`: `info` не сохраняется на диск.

## Архитектура (`Sources/`)

| Файл | Ответственность |
|---|---|
| `main.swift` | точка входа, `.accessory`-приложение |
| `Config.swift` | константы, `Settings` (UserDefaults), логгер |
| `Layout.swift` | `TIS` — раскладки от системы; распознавание удалённых событий |
| `Accessibility.swift` | обёртки над AX API, экраны для `Geometry` |
| `Caret.swift` | поиск позиции курсора (`probeCaret`) |
| `FlagPanel.swift` | окно флага |
| `Controller.swift` | события, таймер, меню в меню-баре |

Чистая логика — в `Sources/Core/` (цель тестов, без AX/TIS/NSEvent; всё системное передаётся параметрами):

| Файл | Ответственность |
|---|---|
| `Script.swift` | письменность символов, `LayoutInfo` (флаг и письменность по id/языку) |
| `LayoutState.swift` | какую раскладку показывать: локальная + удалённая коррекция |
| `DisplayState.swift` | когда флаг виден: скрытие при наборе, пауза, клавиши навигации |
| `Geometry.swift` | `Anchor`/`Probe`, AX → Cocoa, отбраковка прямоугольников, положение флага |

**Новую логику писать в `Core` с тестом.** Системные вызовы — тонким слоем снаружи.

**Поиск курсора** (`probeCaret`), по порядку: `AXBoundsForRange` (`range`, сначала рамка символа `length: 1`, пустой диапазон — последним) → `AXBoundsForTextMarkerRange` (`marker`, WebKit/Chromium) → ширина текста до курсора системным шрифтом (`metrics`, однострочные поля) → слева от поля (`field`) → у указателя мыши (`mouse`, большие поля). Источник виден в меню приложения и в логе.

**Раскладка:** локально — TIS (уведомление с `deliverImmediately` + опрос в `tick`). Удалённо — локальная раскладка не меняется; флаг переключается по Caps Lock от `ScreensharingAgent` и корректируется по письменности набранных букв (`remoteLabel`).

## Особенности приложений (выяснено опытом, не ломать)

- **Electron/Chromium:** дерево доступности включается `AXManualAccessibility`; для Chromium-браузеров ещё `AXEnhancedUserInterface`.
- **Пустое поле Chromium** отдаёт вместо курсора всю строку → `collapsed()`.
- **Омнибокс Chrome:** нет `AXBoundsForRange`, `AXFont` пустой → `metrics`, погрешность ~1% на длинной строке.
- **VS Code:** у пользователя выставлено `editor.accessibilitySupport: off` и отключён `editor.editContext`. Без этого позиция неверная (режим диктора / EditContext). Курсор за пределами видимой области → поле ввода высотой <3 px → флаг прячется.
- **Excel:** на любой диапазон отдаёт рамку всего поля → отбрасывается; `metrics` отключён (`noMetricsApps`) по желанию пользователя — флаг у начала поля. **Тяжёлые AX-запросы (`AXAttributedStringForRange`, обход дерева) роняли Excel — не использовать.**
- **AppKit (`NSTextField`/`NSTextView`, а значит Заметки, Mail, Pages, нативный Telegram):** `AXBoundsForRange` с `length: 0` отдаёт прямоугольник на высоту строки **выше** настоящего курсора; с `length: 1` — верный. Порядок запросов в `caretByRange` менять нельзя.
- **Стенд `CaretHarness`:** проверки запускаются только после того, как его окно стало активным (`NSApp.isActive && isKeyWindow`), иначе фокус и позиция читаются неверно и результат плавает. Запускать, не уводя фокус на другое окно.
- **AX к собственному процессу:** для полей AppKit работает, для внепроцессного содержимого WebKit (`WKWebView`) — нет: позиция и маркеры пустые. Поэтому стенд #011 покрывает только AppKit, для WebKit нужен двухпроцессный (#012).
- **Word:** обычные режимы — `range`; Outline — координат нет, флаг у мыши.
- **Screen Sharing:** Caps Lock приходит парой `flagsChanged` (keyCode 57) от `ScreensharingAgent`; в «чужой» раскладке клиента приходят готовые символы с `keyCode 0`.
- **Удалённое управление** ломает локальное переключение Caps Lock — учитывать при интерпретации тестов.

## Запреты

- Никогда не логировать нажатия клавиш и символы — в лог попадает набранный текст.
- Не менять настройки чужих приложений и системы без явного согласия пользователя.
- Не удалять диагностику, пока требование в работе; удалять перед закрытием требования.

## Цикл разработки

Требования живут в `backlog/` — один файл на требование, формат в `backlog/README.md`. Навыки проекта:

- `/req` — занести новое требование (или дополнить существующее) по итогам обсуждения;
- `/backlog` — показать очередь и предложить, что брать дальше;
- `/analyze <id…>` — исследовать требования, записать анализ и план;
- `/develop <id…>` — реализовать одно требование или группу, проверить с пользователем, закрыть, выпустить версию.

Правила:
- Одно требование или группа = одна версия: запись в `CHANGELOG.md`, версия в `Info.plist` (minor — новое поведение, patch — исправления), коммит `vX.Y.Z: <кратко> (#id, #id)`.
- Git только локальный; push/публикация — только с подтверждения.
- Перед установкой версии прогонять `./test.sh` и `./test-caret.sh`.
- Поведение флага проверяет пользователь глазами: после `./install.sh` дать ему короткий сценарий проверки из требования и дождаться результата. Регрессии — по `docs/test-matrix.md`.
- Новые выясненные особенности приложений — дописывать в раздел выше.
