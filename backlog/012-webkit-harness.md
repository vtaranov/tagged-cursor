## Запрос
Стенд из #011 проверяет только поля AppKit. Нужны автоматические проверки для WebKit (и, если получится, Electron): это ветки `marker` и `collapsed`, то есть основной путь для Chrome, Safari, Claude desktop, Obsidian, Telegram Web.

## Анализ
Выяснено при работе над #011: AX-запросы к **собственному** процессу не доходят до внепроцессного содержимого WebKit. У сфокусированного элемента внутри `WKWebView` в своём же процессе `AXPosition`, `AXSize` и `AXSelectedTextMarkerRange` пустые, хотя `AXRole` читается. `AXManualAccessibility` на свой процесс не помогает. В чужом процессе (реальные Chrome и Safari) всё работает.

Отсюда схема: два процесса.
- **Хост** — приложение с `WKWebView`: страница с contenteditable, обычным input и пустым input с плейсхолдером. Ставит курсор в заданную позицию и записывает эталон (прямоугольник из `Range.getBoundingClientRect`, переведённый в экранные координаты) в файл.
- **Раннер** — вызывает `probeCaret(pid: хост)`, читает эталон из файла, сравнивает. Синхронизация через файл или простой сокет; хост поднимает окно в известной позиции на основном экране.
- Раннеру нужно собственное разрешение Универсального доступа; подписывать тем же сертификатом, чтобы грант не слетал. Хосту разрешение не нужно.
- Открытый вопрос: нужен ли хосту `AXManualAccessibility` от раннера (как приложение делает для Electron) — проверить обе ветки.
